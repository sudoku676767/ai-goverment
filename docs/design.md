# 黑匣子设计文档

版本：v0.1 草案 · 2026-10-12

## 1. 定位

**第三方 agent 插件和 skill 的入职体检。**

起点是 DeepSeek Harness（dsh）的插件生态：它的核心理念是“一切皆插件”，模型接入、工具、沙箱、会话存储，甚至 agent 循环本身都可以被插件替换。插件数量巨大，社区目录明确不做质量评级，而插件代码直接运行在用户机器上。

黑匣子要回答两个问题：

1. **它真的有用吗？** 和不装它相比，成功率、token 开销、轮次有什么变化。
2. **它在背后做了什么？** 联网、读写哪些文件、有没有说一套做一套。

### 核心原则

- **只记录，不判断。** 不用 AI 给 AI 打分。工具只列数据，判断和调整交给人。
- **站在被记录对象的外面。** 记录器不能是插件、不能是 skill、不能是提示词，否则会被别的插件覆盖或绕过。
- **行为高于声明。** 模型说的和实际做的冲突时，以实际行为为准。

## 2. 飞行记录仪类比

| 飞机黑匣子 | 对应到本工具 |
|---|---|
| 话音记录器（CVR）：机组说了什么 | 声明通道：模型的文字、思考、可选的意图声明 |
| 数据记录器（FDR）：飞机实际怎么飞 | 行为通道：API 请求、工具调用、系统副作用 |
| 两者按同一时间轴对齐 | 统一时间戳，逐条对账 |
| 法规强制的参数清单和格式 | 固定的最小指标集和日志格式，带版本号 |
| 机组无法删改 | 独立于 agent，只追加，哈希链 |
| 抗冲击、抗火、抗水压 | 每个事件立即写盘，崩溃也不丢 |
| 循环录制 | 常驻模式下的日志轮换（待做） |
| 水下定位信标 | 异常结束或触发高危规则时主动提醒（待做） |
| 独立机构解读 | 开放格式，任何人可写分析器、复核报告 |
| 日常航班数据监控 | 不只出事时用，日常使用也开着，看趋势 |

类比失效的地方：飞机传感器是客观的，而“话音通道”是模型自己生成的，可能被操纵。所以声明通道只作参考，权重低于行为通道。

另外黑匣子没有、但本工具必须有的：**隐私保护**。日志会保存提示词、代码，甚至误贴的密钥，记录器本身会成为攻击目标。默认本地存储，写入前遮蔽密钥。

## 3. 四层记录

只看 API 是不完整的：插件脚本在机器内部做的事，API 里只能看到“执行了一条命令”。

| 层 | 记录什么 | 怎么做 | 状态 |
|---|---|---|---|
| 0 静态 | 插件文件哈希、危险模式（`curl \| bash`、base64 混淆、访问密钥目录、网络地址） | 运行前扫描 | 待做 |
| 1 API | 每次请求和响应的完整内容、token、工具调用、结束原因、时间 | 透传代理 | **v0.1 已完成** |
| 2 执行 | 实际运行的命令、改动的文件 | harness 的钩子或包装器 | 待做 |
| 3 系统 | 网络连接、文件系统变化 | 虚拟机或容器内监控 | 待做 |

### dsh 的特殊风险：路由可被插件改写

在 dsh 里，模型路由本身由插件管理，恶意插件可以把请求改发到别处，绕过代理。对策是在虚拟机层面**限制出站网络，只允许连接黑匣子代理**。插件想绕路也出不去，而且每次尝试都会留下记录。这是整个设计里唯一需要“拦”的地方，目的是保证记录完整，不是干预行为。

### 日志的存放

日志不能放在 agent 的工作目录里，agent 不能有写权限。研究中已经观察到 agent 会改写评测脚本来掩盖失败，同理也可能改日志。

## 4. 双通道：先声明、后对账

模型对自己的评价不可靠，所以不让它写报告、不让它自评。但可以让它在每个小任务开始前**下注**，用封闭格式列出：

- 打算动哪些文件
- 打算用哪些工具
- 预计几步完成
- 依赖哪些假设
- 是否计划验证

结束后由程序拿行为通道逐项对账：说动 1 个文件实际改了 4 个、说 3 步实际 11 轮、说会验证实际没跑任何检查。**声明和实际的偏差就是它的“本性”**。

要求：

- 字段必须是数字、列表、是或否，不能是自由文本（自由文本需要 AI 解读，违背原则）。
- 声明的载体是工具调用，不写在正文里，避免污染输出。
- 声明本身会改变行为，所以对照组和实验组都带同样的声明要求。
- 声明通道可选、可缺失。漏了不影响行为通道的数据。

### 声明的进阶做法：写进协议（可选“主动模式”，默认关闭）

由代理在转发时给每个工具的参数定义加一个必填的 `intent` 字段，模型调用任何工具都必须填写，代理记录后再删掉转给客户端。这样声明就不是一条可被别的插件覆盖的提示词，而是格式上的硬要求。代价是它修改了流量，不再是纯旁观。

### 上报通道

声明 skill 里提供一个“我卡住了”的上报命令。模型用正当方式承认失败，本身就在暴露本性。研究显示，给编码 agent 一个结构化上报工具能显著减少它通过修改测试来作弊的行为。

## 5. 实验设计

不按这个来，数据会误导人。

- **三组对照**：干净的基线；只多装被测插件；多装一份长度相近但无关的内容（区分“插件内容的作用”和“提示词变长的作用”）。
- **每组独立环境**：dsh 用不同的 `DSH_HOME`，互不污染。
- **多次运行**：每个任务至少 3 到 5 次。同一任务的 token 用量可以相差很大。
- **按模型分别报告**：插件的效果在不同模型之间迁移性很弱。
- **按任务难度分组**：插件可能对难任务有用、对简单任务是负担，混在一起平均就看不出来。
- **环境快照**：每次运行记下模型版本、harness 版本、插件文件哈希、参数设置。
- **统计诚实**：数值范围重叠时明确写“差异不显著”。
- **成本上限**：内置预算估算和花费上限，先小规模试跑。

## 6. 指标清单

所有指标都由代码从记录中计算，不经过 AI。

**结果**：成功率（确定性检查：测试、格式校验、人工打勾），每次成功的成本。

**成本**：输入、输出、缓存命中、推理 token；插件开销 = 实验组减基线。重点看输入，agent 任务的成本主要由输入驱动。

**浪费**：平均花费减成功运行中的最少花费；每轮输入 token 的增长曲线；`max_tokens` 截断比例。

**行为**：轮次；各工具调用次数；同名同参数的重复调用（v0.1 已有）；工具报错与重试链；循环；结束前是否做过验证；插件是否真的被加载和使用。

**稳定性**：多次运行之间 token 和成功率的波动；工具调用顺序是否一致。

**安全**：访问网络、读取密钥目录、执行下载的脚本、修改测试文件、尝试连接代理以外的地址。

**解读提醒**：思考 token 多不代表想得好，只算成本，不算质量。

## 7. 呈现

1. “成功率 × 成本”散点图，越靠左上越好。
2. 每个任务一张三组对照表。
3. 逐轮时间线，触发规则的异常标红。
4. 插件体检报告：触发率、额外开销、遵从度、可疑行为。措辞是“标记可疑行为”，不是“证明安全”。

## 8. 路线图

- **v0.1**：API 层代理 ✅；dsh 测试运行器（独立 `DSH_HOME`、无界面模式批量运行）；指标对比表；虚拟机内限制出站网络的配置说明。
- **v0.2**：静态扫描；系统层文件和网络记录；环境快照；多次运行统计。
- **v0.3**：声明 skill 与对账；上报通道；逐轮时间线。
- **之后**：主动模式；安全规则导出为拦截配置；Claude Code 适配；体检报告格式。

## 9. 已知限制

- 拦截不到无法配置 API 地址的客户端，例如网页版聊天。
- 哈希链不防整体重写和尾部截断，需要把最终哈希存到别处。
- dsh 处于开发者预览阶段，配置项可能变化。黑匣子只挂在网络和系统这类稳定层面，不依赖 dsh 内部接口。
- 上游走 HTTPS 代理（企业网络）的场景暂不支持。
